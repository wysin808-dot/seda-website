## 1. 统计与发布

- CMS 流量、概览、日统计共用过滤逻辑。排除已识别爬虫、带有效 CMS 会话的访问和显式测试事件；保留原始数据，仍不宣称其余全部是真人。
- 来源识别使用域名边界，增加 ChatGPT、Perplexity、Copilot、豆包、Kimi、DeepSeek。没有 referrer 的 AI 点击仍可能属于直接访问，不能完全还原归因。
- 统一新加坡日期；服务器有日期的旧百度响应与 JSONL 台账合并，不能凭 shell 成功推断接收。缺少日期的权限报错仍需服务器 cron 排查。
- 保持仓库主动百度推送禁用，不重新消耗额度；现有服务器是否有额外任务需部署前核对。
- CMS 发布前验证来源/待核实内容；构建后验证文件、canonical、索引指令、地图，再报告发布成功。失败保留草稿状态；已经发布但提交失败不回滚发布状态。
- 原有公开统计接口的默认口令被移除；公开报表需显式配置 `ANALYTICS_REPORT_TOKEN`，旧调用方需同步。未配置时拒绝访问，不公开运营数据，CMS 登录后的统计不受此设置影响。部署仅输出配置是否存在，不输出密钥。
- 日常部署移除历史应急证书进程清理和其他站点证书操作，只读检查 SEDA 证书有效期；不修改现有独立证书续期任务。

## 3. 内容生产

默认由每天 5 篇改为周一/三/五各 1 个研究提纲。`--count` 最多 3；只生成草稿，不会自动发布。已有相同关键词的稿件不再重复生成；该去重不是语义重复检测，编辑仍需查重。

自动分数不再奖励 1500 字或固定 FAQ 数。外部来源不等于事实正确，编辑必须阅读来源、核对年份及适用对象。新稿不得包含 `[待核实]`、`[待补充]` 或 `contentType: research-brief` 才能批准。

没有 AI 返回时生成研究提纲，不再兜底生成泛泛而谈的升学正文。每篇按问题选择必要的表格、实拍或工具，不要求为了凑数量加图。

## 4. 搜索与 AI 引用记录

CMS 提交记录新增当日百度展现、自然点击与出处字段；未核实留空，不自动填零。展现/点击必须来自搜索平台，不能填写 CMS 来源浏览量。

20 个固定问题见 `data/seo/observation-plan.json`。人工在各产品的新对话、联网模式下测试，记录模型、日期、问题、真实引用 URL 与截图/分享链接。没有成功测试为 unavailable，而不是 not_cited；无链接品牌提及不是 cited。

记录工具：

```bash
npm run seo:observe -- add /absolute/path/observation.json
npm run seo:observe -- summary
```

搜索记录格式：

```json
{"type":"search","date":"2026-09-23","platform":"Baidu","periodStart":"2026-09-22","periodEnd":"2026-09-22","evidence":"内部报表位置","indexed":null,"impressions":null,"clicks":null}
```

AI 记录格式（示例，不能作为真实观测录入）：

```json
{"type":"citation","date":"2026-09-23","platform":"ChatGPT","question":"实际测试的问题","model":"实际显示的模型","webEnabled":true,"evidence":"截图或分享链接","result":"unavailable","citedUrls":[]}
```

记录保存在 `data/seo/search-observations.jsonl`，默认不提交 Git，避免将内部证据位置公开。日报运行处没有该文件时必须显示 unmeasured；不会从 CMS 自动获取，跨服务器/Actions 同步仍是下一阶段，不宣称已打通。
